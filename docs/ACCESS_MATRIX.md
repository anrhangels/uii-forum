# Матрица доступа УИИ

Проверки выполняются на сервере. Роль определяется членством в закрытых группах phpBB, а не полями запроса или общим флагом `a_`. Основатель phpBB имеет технический уровень руководства. Для входа обычному участнику также требуется штатное разрешение `u_uii_use`.

| Действие | Сотрудник | Заместитель | Начальник | Руководство фракции |
|---|---|---|---|---|
| Создание дел, протоколов, запросов и проверок | Да | Да | Да | Да |
| Просмотр/изменение дел | Свои и назначенные | Все дела отдела | Все дела отдела | Все дела отдела |
| Назначение ответственного | Нет | Да | Да | Да |
| Закрытие жалобы с обязательными данными | Нет | Да | Да | Да |
| Управление обычными сотрудниками | Нет | Да | Да | Да |
| Создание руководящих аккаунтов и смена руководящих ролей | Нет | Нет | Нет | Да |
| Управление равной или более высокой ролью | Нет | Нет | Нет | Да, кроме основателя |
| Изменение собственного аккаунта через управление сотрудниками | Нет | Нет | Нет | Нет |
| Изменение события начала срока | Нет | Нет | Да | Да |
| Общий административный журнал | Нет | Нет | Да | Да |
| Системная ACP / системная модерация | Нет | Нет | Нет | Только с отдельными штатными правами phpBB |
| Собственный пароль и тема | Да | Да | Да | Да |
| Самостоятельная смена пола и аватара | Нет | Нет | Нет | Нет |
| Личные сообщения и уведомления | Отключены | Отключены | Отключены | Отключены |

Основателя нельзя заблокировать, сбросить или изменить через портал сотрудников. Аккаунты сохраняются при блокировке, сеансы и ключи автологина отзываются. Руководитель может изменить пол другого допустимого сотрудника; аватар выбирается сервером из фиксированного набора. Пути к изображениям от пользователя не принимаются.

Проверены реальные аккаунты всех четырёх ролей: маршруты управления/журнала, изменение регламента, запрет выдачи руководящих ролей начальником и заместителем, запрет изменения себя, управление сотрудником руководством. Дополнительный тест временно выдаёт специально созданному QA-сотруднику `a_board` и `m_uii_manage`: это не открывает ему управление УИИ, чужие дела, темы или системную ACP. Выданные тестовые права снимаются в `finally`.

Личные сообщения, уведомления, загрузка/изменение аватара и старые вкладки UCP закрыты также по прямым ссылкам и POST. Устаревшие страницы профиля и списка пользователей перенаправляются в корпоративные экраны. Служебные доказательства уведомления адресата запроса сохранены: это этап документооборота, не система пользовательских уведомлений.


Обновление 0.8.0: страница настроек интерфейса доступна всем сотрудникам; изменение правила начала срока остаётся только у начальника/руководства. Тема и плотность - локальные настройки браузера. Пол не отображается в профиле/аккаунте; назначение пола остаётся в форме управления сотрудниками с прежними ограничениями. Статистика профиля - агрегированные счётчики, без раскрытия чужих карточек. Предпросмотр фото проверяет те же права дела, что и скачивание. Лимиты 1/2, разные этапы проверки, запрет загрузки после закрытия, CSRF и версия проверяются сервером.


Обновление 0.9.0: редактор общего меню требует уровень 4 и штатный a_; одних административных флагов сотруднику недостаточно. Группы меню не являются группами прав: каталог ссылок и минимальные роли закреплены сервером, служебные ссылки нельзя удалить. Изменения защищены CSRF/версией/транзакцией, записываются в журнал. Сотрудники всех ролей видят список/статус/роль и доступные фильтры; заметки к блокировке - только руководство (2+). Изменение роли, сброс, блокировка/восстановление сохраняют прежнюю иерархию. Должность не используется. Дополнительная политика ACP в service/acp_policy.php отклоняет прямые адреса отключённых модулей, включая числовой i.

# Перенос UII Portal на SpaceWeb

Подготовка для обычного виртуального хостинга с PHP и MySQL. Публикация на аккаунте SpaceWeb ещё не выполнялась. Docker и локальные инструменты разработки на хостинг не переносятся.

## 1. Какие файлы нужны

Полный пакет находится в `release/spaceweb-complete-ДАТА-ВРЕМЯ/` после команды:

```bash
cd /home/anrhangels/uii-forum
sudo bash scripts/prepare-spaceweb.sh
```

Если домен уже выбран, его можно передать единственным аргументом:

```bash
sudo bash scripts/prepare-spaceweb.sh forum.example.ru
```

Команда обновляет локальную базу до текущих миграций с резервной копией, временно приостанавливает web-контейнер, снимает свежую базу и копирует файлы из того же состояния. При ошибке/завершении web-контейнер возобновляется. Источники и пользовательские дела не удаляются. Работающие на ПК пользовательские страницы в момент копирования могут временно не отвечать.

Если папка называется `spaceweb-code-...` и содержит `DATA_REQUIRED.txt`, **это только код, без текущей базы и фотографий**. В `deployment.json` у полного пакета `complete_for_migration: true`. Старые SQL-снимки вместо актуальной базы не подставляются.

| Файл | Что с ним сделать |
|---|---|
| `website.zip` | Распаковать непосредственно в корневую папку сайта, обычно `public_html` |
| `private-files.zip` | Распаковать на один уровень выше корня сайта; появится `uii-private/evidence` |
| `database.sql.gz` | Импортировать в НОВУЮ базу через панель/phpMyAdmin; не размещать в публичной папке |
| `hosting-settings.sql` | Заполнить домен и выполнить после импорта, если нет SSH |
| `private-tools/` | Инструменты проверки/настройки по SSH; держать вне публичной папки |
| `deployment.json` | Состав, статус полноты и SHA-256 артефактов; не требует загрузки на сайт |
| `START_HERE.md` | Эта инструкция |

Пути при размещении в корне домена:

```text
папка_аккаунта_или_сайта/
├── public_html/          ← содержимое website.zip
│   ├── index.php
│   ├── app.php
│   ├── config.php
│   └── .uii-deploy.lock
├── uii-private/          ← private-files.zip, ВНЕ public_html
│   └── evidence/
└── private-tools/        ← необязательные CLI-инструменты
```

Если у сайта другая корневая папка, используйте фактический путь из панели. Пакет рассчитан на установку в корне домена, без `/forum` в URL. `config.php` задаёт путь к фото относительно родителя корневой папки. При другой структуре задайте в `UII_EVIDENCE_PATH` абсолютный приватный путь вне публичного дерева.

## 2. Настройки SpaceWeb

В панели «Сайты» выберите **PHP 8.3**. SpaceWeb описывает переключение версии в конфигурации конкретного сайта; версия CLI проверяется отдельно. Нужны `mysqli`, `mbstring`, `json`, XML/DOM, `ctype`, `hash`, `filter`, `session`, `zlib`. Для графических возможностей ядра оставьте GD. [Инструкция SpaceWeb по PHP](https://help.sweb.ru/kak-izmenit6-versiyu-php-na-hostinge_138.html).

Создайте пустую базу и отдельного пользователя. По документации SpaceWeb для MySQL 8 используются `127.0.0.1` и порт `3308`; для MySQL 5.6/5.7 - `localhost` и обычный порт. **Параметры вашего аккаунта сверяйте в панели.** Шаблон настроен на MySQL 8. [Параметры подключения SpaceWeb](https://help.sweb.ru/parametry-podklyucheniya-k-bd-mysql_958.html).

Подключите домен и HTTPS. Для поддерживаемых тарифов сертификат Let’s Encrypt заказывается в «SSL/Установить». После выпуска настройте перенаправление HTTP → HTTPS средствами панели. [Инструкция SpaceWeb по SSL](https://help.sweb.ru/ustanovka-besplatnogo-sertifikata-let-s-encrypt-s-avtoprodleniem_1213.html).

Тариф, свободное место, лимиты PHP и БД на конкретном аккаунте пока не проверены. Для фото разрешено 500 МиБ, но к ним добавляются код, база и резервные копии. Лимит приложения не резервирует место у провайдера.

## 3. Загрузка кода и файлов

1. В панели привяжите домен к нужной корневой папке. Не распаковывайте весь пакет вместе с SQL в публичный каталог.
2. Сохраните резервную копию уже существующего сайта, если в папке есть собственный контент. Стандартную заглушку `index.html` уберите, чтобы она не перекрывала `index.php`.
3. Распакуйте **содержимое** `website.zip` в корень сайта. Внутри архива нет лишнего уровня `app/`.
4. Распакуйте `private-files.zip` рядом с корнем, не внутри него. Сами фото выдаются через проверку доступа в phpBB, прямых публичных адресов у них нет.
5. Сохраните `.htaccess` из пакета в корне, `files`, `cache`, `store` и расширении. Правила защищают служебные файлы и сохраняют маршрутизацию.
6. PHP-процесс должен иметь запись в `cache`, `files`, `store`, `uii-private/evidence`; права `777` не нужны. Для приватных директорий используйте 750, файлов 640; `config.php` - 600 или 640 с учётом пользователя PHP на аккаунте.
7. Заполните `public_html/config.php`: `$dbhost`, `$dbport`, `$dbname`, `$dbuser`, `$dbpasswd`. Префикс таблиц уже взят из проекта; не придумывайте новый при импорте готовой базы. Пароли в пакет не встроены.

До удаления `.uii-deploy.lock` PHP-страницы отвечают 503 с сообщением о переносе, ещё до подключения к базе. Это позволяет настроить сайт без раннего доступа к тестовым аккаунтам.

Способы загрузки через файловый менеджер/FTP и выбор `public_html` описаны в [инструкции SpaceWeb](https://help.sweb.ru/kak-zagruzit6-sajt-na-hosting_940.html). Если у вас уже собственный `.htaccess`, сохраните копию и согласуйте его с правилами phpBB; не удаляйте действующие настройки без разбора.

## 4. Импорт базы

Импортируйте `database.sql.gz` в созданную пустую базу через раздел «Базы данных» либо phpMyAdmin. Это существующий установленный форум: повторная установка phpBB не нужна, папки `install/` в пакете нет.

Экспорт не содержит команд создания чужой базы/переключения на локальное имя. При упаковке убирается директива sandbox клиента MariaDB; в DDL алиасы `utf8mb3` приводятся к совместимым `utf8`, без изменения текста материалов. SQL-доступы локального Docker не используются для SpaceWeb.

[Миграция файлов и базы по инструкции SpaceWeb](https://help.sweb.ru/migraciya-sajta-pri-pomoshi-komandnoj-stroki_1255.html).

## 5. Настройка после импорта

### С SSH

Убедитесь через `php -v`, что используется нужный PHP (целевая версия 8.3). Загрузите `private-tools` вне публичного каталога и сначала выполните проверку:

```bash
php private-tools/setup-spaceweb.php /полный/путь/public_html forum.example.ru
```

Проверка не меняет базу: смотрит PHP-модули, конфигурацию, актуальные таблицы v014, приватную папку и **каждое фото, на которое ссылаются дела**. Отсутствующие/повреждённые файлы не замалчиваются. Пароли не выводятся.

Затем примените настройки:

```bash
php private-tools/setup-spaceweb.php /полный/путь/public_html forum.example.ru --apply --unlock
```

Настроятся домен, HTTPS, путь `/`, безопасные cookie и новое имя cookie. Сеансы/автологин старого компьютера будут сброшены. `Qatest_*` заблокируются только на новой копии, дела сохранятся. Форум останется выключенным для сотрудников; основатель сможет войти для проверки. PHP-блокировка переноса снимется только после успешной настройки.

### Без SSH

1. В `hosting-settings.sql` замените `REPLACE_WITH_DOMAIN` реальным доменом, без `https://`, порта и пути. Если при сборке домен был передан, он уже заполнен.
2. Выполните этот SQL **в новой базе SpaceWeb после импорта**. Он меняет настройки/cookie, закрывает тестовые аккаунты и сбрасывает старые сеансы, не удаляет дела.
3. Убедитесь в файловом менеджере, что все `.bin` фото из полного `private-files.zip` распакованы в приватную папку. Проверку связи каждой фотографии лучше выполнить CLI-инструментом при доступном SSH; без неё автоматической сверки нет.
4. Удалите `.uii-deploy.lock` из корня сайта. Форум остаётся выключенным настройкой phpBB, основатель может войти для проверки.

На локальной базе ничего из `hosting-settings.sql` выполнять не нужно. SQL, архивы данных и инструменты не должны оставаться в `public_html`.

## 6. Проверка перед открытием

Войти существующим основателем (`Test_Admin`, текущий локальный пароль), изменить пароль на рабочий и проверить:

- HTTPS и переход с HTTP, отсутствие ссылок/редиректов на `127.0.0.1:8088`;
- русский интерфейс, обе палитры, статические портреты и мобильное меню;
- свою/чужую карточку, обсуждение, фото в карточке и скачивание;
- новый протокол/проверку: 1/2 фото, 2 МиБ на файл, общая квота 500 МиБ;
- сотрудников, блокировку/отзыв сеанса и фильтры;
- управление меню, системную ACP и закрытые разделы;
- запрет прямой выдачи `/files/` и PHP-классов расширения.

Проверьте, что тестовые `Qatest_*` заблокированы. Затем в ACP выключите режим «Форум отключён». Редактор меню доступен через «Управление → Левое меню». Почта/публичная регистрация должны остаться отключёнными.

`.user.ini` в пакете предлагает `upload_max_filesize=2M`, `post_max_size=8M`, выключенный вывод PHP-ошибок. Это применяется только в поддерживающем `.user.ini` режиме; реальные значения сверяйте в панели SpaceWeb. Если директивы не применяются, выставьте ограничения в настройках PHP сайта.

## 7. Обслуживание и пределы готовности

Резервная копия на SpaceWeb должна включать **базу + публичные файлы + uii-private**. Одной копии `public_html` для фото недостаточно. Срок запросов вычисляется сервером при обращении, отдельный фоновый планировщик порталу не нужен; технический cron phpBB сохранён.

Код и состав архивов проверены локально. Фактическое окружение SpaceWeb, импорт в его MySQL, HTTPS, веб-права и нагрузка ещё не проверялись. Docker из среды агента недоступен: начальный подготовленный пакет `spaceweb-code-*` не объявляется полным переносом. Полные данные добавляются только свежим экспортом через `prepare-spaceweb.sh`.

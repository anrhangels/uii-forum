## Изменения базы данных

Миграция **v016** зависит от v015 и добавляет две таблицы с фактическим префиксом установленного phpBB:

- `uii_bug_reports`: `report_id`, `user_id`, `title`, `category`, `description`, `reproduction_steps`, `expected_behavior`, `evidence_url`, `status`, `created_at`, `updated_at`, `version`, `submission_key`.
- `uii_bug_submit_state`: `user_id` и `version` — строка сериализации отправок конкретного пользователя.

Индексы отчётов: первичный идентификатор; уникальный ключ отправки; `(created_at, report_id)` для сортировки; `(status, created_at, report_id)` для фильтра; `(user_id, created_at)` для проверки частоты. Во второй таблице только первичный ключ пользователя.

Автор хранится как идентификатор phpBB. Актуальный никнейм получается JOIN с существующей таблицей пользователей. Удалённая учётная запись не уничтожает отчёт. Миграция не создаёт вторую систему пользователей, не меняет существующие дела и сохраняет пользовательскую структуру меню, дополняя её двумя ссылками. Обратная разрушительная миграция отсутствует: отчёты остаются при отключении расширения.

## Реализованные функции

### Отправка и права доступа

Пункт **«Сообщить об ошибке»** находится в группе «Отдел». Форма доступна только зарегистрированному пользователю с разрешением `u_uii_bug_report`. Миграция разрешает отправку четырём существующим группам сотрудников УИИ. Заблокированные аккаунты и обязательная смена пароля обрабатываются прежними механизмами.

Поля:

| Поле | Ограничение |
|---|---|
| Название | Обязательно, 1–150 символов |
| Раздел сайта | Обязательный выбор из восьми вариантов |
| Описание | Обязательно, 20–10 000 символов |
| Воспроизведение | Необязательно, до 5 000 символов |
| Ожидаемое поведение | Необязательно, до 5 000 символов |
| Доказательство | Необязательно, HTTP/HTTPS URL до 2 048 символов |

После отправки показывается реальный номер `BR-0001` и сообщение об успешном сохранении. Числа после 9999 не обрезаются. Подтверждение доступно только автору соответствующей записи и не содержит текста отчёта. Пользовательского списка обращений нет.

Административная ссылка **«Баг-репорты»** добавлена в группу «Управление». Доступ проверяется по **`a_uii_bug_reports`**, а не по должности, `m_uii_manage` или одному лишь наличию общего `a_`. Основатель форума сохраняет полные права согласно штатной модели phpBB. Другим администраторам необходимо явно выдать новое разрешение.

Административная страница использует действующую авторизацию и оформление УИИ. На странице не более 20 записей; сортировка по дате в обоих направлениях и фильтр четырёх статусов. Доступны просмотр, переход по доказательству и смена статуса: «Новый», «В работе», «Исправлен», «Отклонён». Исходный текст, автор и дата создания при смене статуса не меняются. Устаревшая версия карточки не перезаписывает чужое изменение.

### Защита

Автор определяется из серверной сессии; переданный клиентом `user_id` не используется. Все изменения требуют CSRF-токена. Валидация выполняется на сервере. Пользовательский текст выводится с явным экранированием, включая содержимое textarea экспорта. Внешние изображения не встраиваются и автоматически не загружаются; ссылка открывается с `noopener`, `noreferrer` и без передачи реферера. URL с логином/паролем, javascript/data/file и неподдерживаемыми схемами отклоняются.

SQL выполняется через стандартный DBAL phpBB с `sql_build_array`, экранированием строк и целочисленными идентификаторами. Сортировка и фильтры выбираются из белых списков. Дубли с одним ключом отправки возвращают первоначальный номер. Ограничение **три успешных отправки за скользящие десять минут на автора** действует также для параллельных запросов из разных сессий: операции сериализуются записью служебной строки внутри транзакции. Неудачная запись откатывается; пользователю показывается понятная ошибка без SQL и внутреннего исключения.

### Передача в Codex

Кнопка **«Скопировать для Codex»** формирует номер, раздел, название, описание, воспроизведение, ожидаемое поведение, доказательство и согласованное задание для Codex.

Пользовательский блок помечен как непроверенные данные и заключён в текстовый блок с разделителем длиннее всех последовательностей обратных кавычек в исходном сообщении. Текст отчёта не считается разрешением выполнять команды или менять файлы. Никакие API Codex, автоматическая отправка или исполнение не добавлены.

На HTTPS/localhost используется Clipboard API. Для обычного HTTP предусмотрен резервный способ копирования через выделенный временный textarea. При запрете со стороны браузера открывается текст для ручного копирования. Уведомление об успехе выводится только после успешного вызова копирования.

### Страница входа

Вместо боковой панели и двух больших блоков — одна центрированная карточка с существующей векторной иллюстрацией, никнеймом, паролем и кнопкой входа. Переключение темы находится отдельно в углу. Сохранены «Запомнить меня», ошибки, CAPTCHA, скрытые поля, токен, перенаправление и условия повторной административной авторизации phpBB. Локальные стили наведения и фокуса сохраняют читаемые цвета в тёмной теме.

### Вставка скриншотов и просмотр изображений дел

В существующих полях изображений дел можно нажать на область выбора и затем **Ctrl+V**. Вставляется одно изображение JPG/PNG/WebP с обычным предпросмотром, возможностью очистки и замены. Дальнейшая загрузка, сжатие, лимит 5 МиБ и приватное хранение используют прежнюю безопасную реализацию дел. Буфер не читается автоматически при открытии страницы; обрабатывается только действие вставки пользователя. Если браузер не передаёт изображение, можно сохранить скриншот и выбрать файл кнопкой.

В **баг-репортах загрузки изображений нет** — там оставлена ссылка на фотохостинг, согласно согласованному плану.

Новые ссылки «Открыть изображение» ведут на `/uii/images/{id}?token=...`: отдельную страницу с центрированным изображением, вписанным в экран. Есть оригинал и скачивание. Перед показом повторно используется та же проверка доступа и наличия файла, что и для бинарной выдачи. Ответ не кешируется. Прежние прямые ссылки `/uii/photos/{id}` сохранены; открытие «Оригинала» отдаёт файл, отображением которого управляет браузер. Старые внешние ссылки также продолжают открываться на исходном сайте.

### Ошибка 404

Несуществующие маршруты приложения показывают страницу **«404 — Страница не найдена»**. Доступна гостям и авторизованным пользователям; есть вход/главная и кнопка назад. Исходный неверный адрес не вставляется в HTML. Сервер возвращает настоящий статус **404**, `noindex` и отсутствие кеширования. Закрытые существующие маршруты не становятся публичными. Для AJAX сохранены штатные JSON-ошибки phpBB.

Docker/Apache получает `ErrorDocument 404 /app.php/uii/not-found`. Текущий `.htaccess` уже направляет несуществующие пути в `app.php`. На отдельном Nginx-хостинге нужно сохранить маршрутизацию несуществующих путей через front controller; нельзя перенаправлять ошибки на главную с кодом 200. При установке в подкаталог путь ErrorDocument должен включать этот подкаталог.

## Проверки и результаты

Выполнены в **отдельной** полной установке phpBB 3.3.19 с SQLite3, локальным PHP 8.5 и GD. Рабочая БД ноутбука не использовалась.

- 26 проверок контрактов: Unicode-лимиты, URL, формат номера, безопасное обрамление экспорта, отдельные права меню.
- 11 групп HTTP-проверок: обычный автор, реальная запись/номер, гости, приватное подтверждение, обязательность и длины, CSRF, XSS, ссылки, идемпотентность, частота, параллельные сессии, смена статуса, сохранение исходного текста, устаревшая версия, сортировка/фильтр/пагинация, выдача и отзыв отдельного ACL без руководящей роли. Отдельно смоделирован отказ INSERT: понятная ошибка и отсутствие частичного отчёта.
- Chromium: вход на 360/768/1440 в двух темах; наведение/фокус; 18 сочетаний административных/пользовательских страниц и размеров/тем; отсутствие исполнения XSS; реальное копирование текста, резервный и ручной варианты; отправка формы; реальная вставка PNG из Clipboard через Ctrl+V и сохранение; центрирование изображений на трёх ширинах; отказ гостю.
- 404: гость, авторизованный пользователь, отсутствующее дело, явный маршрут ошибки, JSON для AJAX, обе темы и три ширины.
- Чистая установка нового пакета: миграция v016, две пустые таблицы, разрешения и новые ссылки меню; русский установщик проверен в обеих темах на трёх ширинах.
- Регрессия дел: 13 HTTP-групп версии 1.1.0 и браузерные проверки трёх форм/загрузки на трёх ширинах. Базовые проверки прав, шаблонов, локализации, кеша, оптимизации изображений и контраста продолжают проходить.

Команды: `bash scripts/test-all.sh` для локальных проверок; `UII_BUG_HTTP=1 bash scripts/test-bugs.sh` для изолированной интеграции. Интеграция требует отдельного сервера `runtime/cases-v2-sandbox/site` на 127.0.0.1:8094, SQLite3/GD и тестового браузера. Тесты изменяют только собственные тестовые данные и не предназначены для рабочего сервера. Нагрузочное тестирование не проводилось.

## Известные ограничения

- Обновление ноутбука ещё не выполнено: доступ к SSH без интерактивного пароля недоступен. Docker/MariaDB 10.11/PHP 8.3 и Apache на ноутбуке нужно проверить после развёртывания; результаты интеграции выше относятся к SQLite/PHP 8.5. Конфигурация ErrorDocument подготовлена, но живой Apache в этом запуске не запускался.
- Доступ к буферу и разрешение копирования зависят от браузера. Если автоматическое копирование запрещено, предусмотрено ручное; если вставка изображения не поддерживается, остаётся выбор файла.
- Приватность старого внешнего изображения определяется фотохостингом. УИИ не может закрыть публичную ссылку на стороннем сайте.
- CAPTCHA и внешние провайдеры входа сохранены в шаблоне; все возможные сторонние провайдеры и виды CAPTCHA в этом окружении не проверялись.

## Настройка прав после обновления

1. Основатель входит в штатную **панель управления форумом → Права доступа**.
2. Для обработки отчётов выбрать **Администраторы**, нужного пользователя, открыть расширенные права и раздел **«Разное»**. Установить «Может просматривать и обрабатывать закрытые баг-репорты УИИ» в **«Да»**.
3. Если нужно разрешить отправку пользователю вне групп сотрудников, открыть его пользовательские права и разрешить «Может сообщать об ошибках УИИ». Обычный доступ ко всем делам это не предоставляет.
4. Проверить отдельной обычной учётной записью: доступна форма, административный список закрыт. Для администратора с новым разрешением появляется пункт «Баг-репорты».

## Развёртывание на ноутбуке

Пакет `uii-update-1.2.0.tar.gz` не содержит `.env`, `app/config.php`, `compose.yaml`, БД, кеша или пользовательских вложений. Текущие адреса и доступ Tailscale сохраняются. Не использовать архив чистой установки для обновления действующего сайта.

На основном компьютере:

```bash
scp /home/anrhangels/uii-forum/release/uii-update-1.2.0/uii-update-1.2.0.tar.gz \
    /home/anrhangels/uii-forum/release/uii-update-1.2.0/SHA256SUMS \
    anrhangels@192.168.1.6:~/
```

На ноутбуке проверить архив:

```bash
cd ~
sha256sum -c SHA256SUMS
```

При успешной проверке выполнить:

```bash
(
    set -e
    umask 077
    cd ~/uii-demo
    backup_dir=$(mktemp -d "$HOME/uii-before-1.2.0.XXXXXX")
    echo "Резервная копия: $backup_dir"
    sudo docker compose stop web
    sudo docker compose exec -T db sh -c '
        export MYSQL_PWD="$MARIADB_ROOT_PASSWORD"
        exec mariadb-dump --single-transaction --user=root "$MARIADB_DATABASE"
    ' > "$backup_dir/database.sql"
    sudo tar -czf "$backup_dir/code.tar.gz" \
        app/ext/uii/portal app/styles/uii_modern Dockerfile deployment scripts docs README.md
    sudo tar --no-same-owner -xzf "$HOME/uii-update-1.2.0.tar.gz" -C "$HOME/uii-demo"
    sudo docker compose build web
    sudo docker compose up -d web
    sudo docker compose exec -T --user www-data web php bin/phpbbcli.php db:migrate
    sudo docker compose exec -T --user www-data web php bin/phpbbcli.php cache:purge
    echo "Обновление завершено. Резервная копия: $backup_dir"
)
```

При любой ошибке блок останавливается: сохранить вывод и не продолжать наугад. При успешном завершении обновить браузер с Ctrl+F5, проверить вход, `/app.php/uii/bugs/new`, административный доступ, вставку в дело, центрированный просмотр и неверный адрес. Текущие адреса остаются `http://192.168.1.6:8088/` и `http://100.99.218.9:8088/` через Tailscale.

Новых зависимостей или фоновых сервисов не требуется. Лимиты PHP для изображений дел остаются 5M/20M и три файла. Для этой версии нужна пересборка web ради Apache ErrorDocument; миграция v016 обязательна.

## Откат

Остановить `web`, восстановить исходники из `code.tar.gz`, пересобрать прежний образ и очистить кеш от `www-data`. Добавленные таблицы отчётов удалять не нужно. Если восстанавливается версия 1.1.0, её сохранённое меню из резервной копии БД не содержит новых ссылок; без восстановления БД старая проверка меню может переключиться на стандартное меню. Поэтому перед откатом сохранить актуальный payload `uii_navigation` для последующего возврата.

Полное восстановление `database.sql` отменит также отправленные после резервной копии баг-репорты и изменения дел. Не выполнять его без понимания последствий; перед восстановлением отдельно сохранить актуальную БД. Пользовательские файлы этот пакет не удаляет.

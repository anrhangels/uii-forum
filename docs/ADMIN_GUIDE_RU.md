# Руководство администратора УИИ 1.0.4

## С чего начать

Рабочий адрес локального проекта: http://127.0.0.1:8088/. Основатель phpBB имеет технический доступ. Пароли не включены в документацию. Новые аккаунты сотрудников создаются руководителем; публичная самостоятельная регистрация закрыта.

Откройте меню профиля → **Управление**. Рабочие настройки отделены от технических параметров phpBB по назначению. Не изменяйте служебные группы УИИ вручную через базу.

## Сотрудники и доступ

**Управление → Сотрудники → Добавить**. Никнейм: Name_Surname латиницей, общая длина до 20 символов. Выберите пол персонажа и бизнес-роль. После создания браузер скачает TXT с временным паролем; передайте его сотруднику защищённым способом. При первом входе сотрудник задаёт собственный пароль.

Роли:

| Роль | Возможности |
|---|---|
| Сотрудник | Свои и назначенные дела, материалы и обсуждения в пределах серверных прав |
| Заместитель | Дела отдела, назначения, управление обычными сотрудниками |
| Начальник | То же, журнал отдела и изменение правила 48 часов |
| Руководство фракции | Управление бизнес-ролями; системная панель и редактор меню дополнительно требуют административного права phpBB |
| Основатель phpBB | Технический доступ; его аккаунт защищён от изменения через форму сотрудников |

Точная матрица: [ACCESS_MATRIX.md](ACCESS_MATRIX.md). Общий флаг a_ сам по себе не делает сотрудника руководителем фракции. Технические ссылки показываются с учётом отдельных прав phpBB.

В строке сотрудника нажмите **Управлять**. Доступны отдельные формы роли/пола, сброса пароля и блокировки/восстановления. Руководитель не меняет собственную роль. Начальник и заместитель не повышают сотрудников до руководства. Блокировка отзывает сеансы, но сохраняет дела и историю. Сброс пароля не снимает блокировку.

Поиск и фильтры работают на сервере, список разбит на страницы. «В сети» означает видимый недавний сеанс, а не предыдущий вход. Опция скрытого сеанса убрана с формы входа; существующие настройки сеансов массово не переписывались.

## Настройки портала

**Управление → Настройки**:

- Тема: светлая, глубокая тёмная или как на устройстве. Сохраняется в текущем браузере; для другого браузера выбирается отдельно.
- Плотность: обычная или компактная, также сохраняется в браузере.
- Начало 48 часов: подтверждение уведомления либо публикации. Изменяет начальник или руководство фракции. Уже начатые сроки не пересчитываются.
- Фотографии: видны действующие ограничения. Начальник и руководство видят объём хранилища.

Числа лимитов фотографий — действующие ограничения, а не редактируемые поля. Квота 500 МиБ на всё хранилище, до 2 МиБ и 24 мегапикселей на изображение; JPG, PNG, WebP. Жалоба: одно фото протокола; проверка: начало и окончание; запросы — ссылки без загрузки фото. Новые фотографии оптимизируются перед сохранением: JPEG/WebP — качество 85, PNG — сжатие без потерь. При достаточной памяти длинная сторона уменьшается до 2560 пикселей; файл заменяется только при уменьшении объёма минимум на 5%. Формат сохраняется. При отсутствии нужного кодека GD, нехватке памяти или ошибке оптимизации сохраняется допустимый исходник. Старые фотографии не переписываются. Увеличение лимитов требует оценки диска, прав и резервного копирования.

## Меню

**Управление → Левое меню** доступно руководству фракции с административным правом. Можно создавать до восьми групп, переименовывать, переставлять и переносить пункты. Используйте перетаскивание, стрелки или список назначения. После изменения нажмите «Сохранить».

Права закреплены серверным каталогом: перенос ссылки не выдаёт доступ. Обязательные пункты нельзя удалить. Пустые группы скрываются; удалить можно только пустую группу. При конфликте версий обновите страницу и повторите изменения. «Стандартное меню» возвращает исходную раскладку; несохранённые изменения нужно подтвердить сохранением.

## Жалобы

Откройте **Жалобы → Создать дело**. Заполните название, заявителя, фигуранта, описание и основание. Руководитель выбирает ответственного. Под полями есть пояснения.

Сохраните материалы. Для протокола заполните текстовый раздел либо загрузите одно фото в карточке. Остальные доказательства — HTTP(S)-ссылки. Перед завершением нужны протокол, доказательства, решение и сведения о нарушениях; при их отсутствии напишите «Не установлены». Жалобу завершает руководитель.

## Служебные запросы

Создайте запрос с адресатом, описанием и основанием. Добавьте доказательство запроса и события, от которого начинается срок. Выберите «Подтвердить начало срока 48 часов» и сохраните. Отсчёт фиксируется сервером, не часами браузера.

Добавьте ссылку на ответ; время ответа фиксируется при первом сохранении. Ответ нельзя затем удалить. Отображается своевременный либо поздний ответ. Завершение без ответа доступно руководителю только после истечения срока и с основанием. Завершение не превращает отсутствие ответа в полученный ответ.

## Проверки

Выберите плановую или внеплановую проверку в списке. Дата и время — по Москве, формат ГГГГ-ММ-ДД ЧЧ:ММ; пример приведён под полем. При пустой дате используется текущее московское время.

После сохранения добавьте фото начала или ссылку. Действием «Начать проверку» зафиксируйте начало. Для завершения нужны материалы начала/окончания, результат и сведения о нарушениях. Дополнительные материалы ссылкой необязательны. Отмена закрывает проверку с отдельным состоянием.

## Обсуждение, архив и конфликты

Новое дело создаёт связанную форумную тему. В карточке находится переход к обсуждению. Первое служебное сообщение редактируется через карточку; комментарии — через редактор сообщений. После завершения дела обсуждение блокируется.

Реестр, задачи и журнал имеют переходы по страницам. Поиск реестра ищет в названии, а не в полном тексте материалов. Фильтр архива показывает завершённые дела. Обычный сотрудник не получает доступ к чужому делу через прямую ссылку.

Если другой сотрудник уже изменил дело, старая версия формы не сохраняется. Скопируйте собственный несохранённый текст, обновите карточку, сопоставьте изменения. Не пытайтесь обходить проверку версии через ручной запрос.

## Техническая панель форума

В центре управления оставлены только функции УИИ и одна кнопка «Открыть панель управления форумом». Дублирующие карточки технических настроек убраны. В самой системной панели выбирайте нужные настройки по назначению:

1. **Форум и обсуждения** — разделы и их права. Не удаляйте три служебных раздела УИИ: они связаны с конфигурацией и темами дел.
2. **Оформление и язык** — стили, языковые пакеты, название сайта. UII Modern наследует prosilver; оба должны сохраняться.
3. **Безопасность и вход** — защита входа, CAPTCHA, cookies и сеансы/нагрузка. Сначала запишите исходные значения. Неверный домен или путь cookies может нарушить авторизацию.
4. **Обслуживание** — резервное копирование БД, журнал администратора, расширения, обзор системы.

При входе phpBB повторно запрашивает пароль администратора. Используйте ссылки интерфейса: ACP требует идентификатор текущего сеанса. Не передавайте административные URL другим пользователям.

Рядом с полями сохраняются штатные русские объяснения; скрипт ACP связывает их с полями для экранных дикторов. Некоторые функции phpBB намеренно отключены политикой портала. Не включайте их через прямые адреса в обход интерфейса.

## Запуск и обновление Docker

```bash
sudo systemctl start docker
cd /home/anrhangels/uii-forum
sudo bash scripts/start.sh
```

Штатное обновление с резервной копией и миграциями:

```bash
sudo bash scripts/apply-portal.sh
```

Затем обновите страницу с Ctrl+F5. В 1.0.0 новая схема БД не добавлена. Dockerfile дополнен конфигурацией сжатия статики и OPcache; она вступает в силу только после пересборки контейнера. Исходники подключены томом и обновляются отдельно от образа. Не выполняйте `docker compose down -v`: это уничтожает volume БД.

На обычном хостинге сохраните резервную копию, замените код без перезаписи config.php и загруженных файлов, выполните штатные `db:migrate` и `cache:purge` через phpBB CLI. Права файлов и версия PHP должны соответствовать веб-серверу. Если CLI недоступен, используйте поддерживаемый провайдером способ обновления phpBB; не выставляйте административные скрипты в публичный доступ.

## Резервное копирование и откат

Нужны одновременно: SQL-дамп, config.php, загруженные файлы (включая приватные фото), версия кода и сведения о размещении хранилища. Скрипты Docker: `scripts/backup-db.sh`, перенос: `scripts/prepare-spaceweb.sh`. Копии содержат закрытые данные и должны храниться вне сайта с ограниченными правами.

Перед восстановлением закройте доступ на запись. Для изменений 1.0.0 без миграции схемы код можно вернуть из `snapshots/pre-audit-*`, затем сбросить кэш. Не импортируйте старую БД поверх новых дел ради отката CSS: это потеряет данные. Полное восстановление требует согласованной копии БД и фото на один момент времени. Порядок переноса и проверки фото — [spaceweb.md](spaceweb.md).

## Диагностика

```bash
bash scripts/php-local.sh tests/localization.php
bash scripts/php-local.sh tests/templates.php
python3 tests/visual_assets.py
```

`php-local.sh` использует вспомогательный PHP CLI проекта, не Docker PHP. Для диагностики БД используйте `php scripts/php/diagnose.php /полный/путь/config.php` в приватной среде. Скрипт выполняет SHOW/SELECT/EXPLAIN и не меняет настройки; результат содержит технические имена таблиц, не публикуйте его без проверки.

HTTP-тесты создают QA-записи. Не запускайте полный `scripts/test-all.sh` на публичном сервере без тестового окна и отдельного тестового администратора. Нагрузочные проверки 1/5/10/20 пользователей предназначены для отдельного стенда.

## Частые проблемы

| Симптом | Что проверить |
|---|---|
| Изменения не видны | Кэш phpBB, версию ресурса, Ctrl+F5, OPcache и обновление образа |
| Невозможно войти в ACP | Бизнес-роль, отдельные права phpBB, повторную авторизацию и актуальный SID |
| Ошибка версии дела | Обновить карточку и сопоставить параллельные изменения |
| Фото не загружается | Тип/размер/разрешение, слот, закрытое состояние дела, квоту, права каталога, post_max_size/upload_max_filesize |
| Пропали фото после переноса | UII_EVIDENCE_PATH и полноту приватного архива; не создавайте пустое хранилище вместо потерянных файлов |
| Docker недоступен | Службу Docker и права пользователя; сайт может работать, даже если CLI не имеет доступа к сокету |
| Английская надпись | Русский язык пользователя/форума, целостность пакета ru, собственные ключи расширения и сброс кэша |
| Не находится дело | Фильтры типа/архива/состояния, страницы, права автора/исполнителя; поиск выполняется по названию |

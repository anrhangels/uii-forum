# Перенос UII Portal на Beget Free

Перенос не выполнялся. Проект работает локально на PHP 8.3, MariaDB и phpBB 3.3.19. Production состоит из содержимого `app/` и одной MySQL-базы. Docker, Node.js, Playwright и локальный PHP CLI на хостинг переносить не нужно.

## Ограничения тарифа

По официальным правилам https://beget.com/ru/rulesfree (проверено 05.11.2026): до 96 МБ памяти на процесс и до 20 одновременных MySQL-соединений; отправка почты запрещена; запрещены слушающие сокеты; исходящие TCP-соединения ограничены портом 80. При превышении лимита нагрузки может включаться кэшируемый режим без передачи cookies, вследствие чего PHP-сессии перестают работать до следующих суток. Для закрытого портала это существенное ограничение: авторизация может стать недоступной. Совместимость по нагрузке на реальном тарифе не проверена.

Страница тарифа: https://beget.com/ru/hosting/free . Перед переносом проверить в панели доступность PHP 8.1+ (предпочтительно 8.3), MySQL/MariaDB, mbstring, mysqli, XML, JSON и HTTPS. Без HTTPS публичный рабочий запуск не проводить. Если HTTPS недоступен на конкретном бесплатном аккаунте, полноценное защищённое размещение на нём не соответствует ТЗ; локальная версия при этом работает.

## Подготовка

1. Сделать SQL-дамп через `sudo bash scripts/backup-db.sh`, сохранить его вне хостинга.
2. Скопировать `app/` в отдельный каталог переноса. Не включать `runtime`, `snapshots`, `downloads`, `backups`, `.env`, тесты и исходные RP-материалы `reference/`.
3. Не переносить содержимое `cache/production`. Оставить защитные `.htaccess` и `index.htm` в `cache`, `files`, `store`.
4. Удаление тестовых аккаунтов не требуется: заблокировать все `Qatest_*` в интерфейсе сотрудников. Дела с префиксом `QA:` — тестовые. Их можно сохранить в архиве; автоматического удаления пользовательских данных нет.
5. Заменить тестовый пароль первого администратора и тестовую контактную почту на рабочие данные, когда они будут определены. Отправка писем должна остаться отключённой.

## Файлы и база

1. Создать одну MySQL-базу в панели Beget. Импортировать дамп в пустую базу через phpMyAdmin.
2. Загрузить содержимое подготовленного `app/` в корень сайта. Каталога `install/` в публичном корне быть не должно.
3. Обновить только реквизиты подключения в `config.php`: `$dbhost`, `$dbport`, `$dbname`, `$dbuser`, `$dbpasswd`. Это штатная конфигурация phpBB. Не переносить IP `172.18.0.2` из локального служебного окружения.
4. Выдать права записи PHP-процессу на `cache`, `files`, `store`, `images/avatars/upload` согласно инструкции хостинга. `config.php` не должен быть доступен для записи веб-процессу после настройки. Не отключать защитные `.htaccess`.
5. В ACP проверить домен, путь, протокол `https://`, порт 443, cookie domain/path и Secure cookies. Удалить старые cookies браузера при смене домена.
6. Включены должны быть `uii/portal`, тема UII Modern и локаль `ru`; VigLink должен быть отключён, `allow_cdn=0`, регистрация отключена. Код 0.9.0 содержит миграции v001-v014; какие из них есть в переносимом дампе, нужно проверить на исходной установке. Новые миграции выполнять через менеджер расширений либо phpBB CLI, если CLI доступен на тарифе.

## Проверка перед доступом сотрудников

Проверить гостевой запрет на главную, карточку, тему и вложение; вход всех ролей; смену временного пароля; немедленную блокировку сеанса; CSRF; создание и закрытие трёх типов дел; серверный срок; выдачу TXT; мобильную раскладку. Не считать локальные тесты доказательством работоспособности окружения Beget.

В расширении нет фонового таймера: сроки вычисляются на запросе. Почта отключена, внешние картинки не скачиваются сервером, с версии 0.6.0 фото протоколов опроса и проверок сохраняются в `files/uii_evidence/`, остальные доказательства сохраняются как ссылки. Каталог files обязательно включать в резервную копию вместе с SQL. Для фото установлена отдельная общая квота 500 МиБ, 1 фото протокола на жалобу и 2 фото (начало/окончание) на проверку, до 2 МБ каждый файл. Прямой доступ к `/files/` должен быть закрыт веб-сервером; проверить 403 для реального файла до открытия доступа сотрудникам. Для штатных вложений задано 256 КБ на файл, 3 файла на сообщение и суммарная квота 20 МБ; аватары до 256 КБ. Продолжать контролировать место базы, журналов и резервных копий в пределах 1 ГБ. Локальная папка `app/` занимает около 36 МБ; размер базы растёт с документами.

С версии 0.5 аватары пользователей - фиксированные локальные SVG из расширения; настройки самостоятельной загрузки отключены. При переносе сохранить `.htaccess` расширения, закрывающий прямой веб-запуск его PHP-классов. Старые PM/уведомления недоступны; таблицы ядра сохраняются для обновлений phpBB.

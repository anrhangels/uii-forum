# Цвета статусов и сжатие изображений — 1.0.4

## Единые отметки

Общий сервис case_status вычисляет подпись и цвет для главной, реестра, задач и карточки дела, без изменения хранимых состояний. Цвет больше не назначается только по наличию срока запроса.

| Состояние | Цвет |
|---|---|
| Создано | Синий |
| Запланирована | Фиолетовый |
| В работе / активен | Зелёный |
| Ожидает ответа | Жёлтый |
| До срока не более 6 часов | Оранжевый |
| Срок истёк | Яркий красный |
| Ответ вовремя | Бирюзовый |
| Ответ с опозданием | Оранжевый |
| Завершено / отменена / доступ закрыт | Красный |

Подписи сохраняются: значение не передаётся одним только цветом. Идентификаторы дел и другие нейтральные метки остаются нейтральными. В браузере проверены реальные главная/реестр/архив/задачи/карточка и все десять состояний в обеих темах; контраст текста меток не ниже 4.5:1.

## Новые изображения

image_optimizer применяется к новым фотографиям дел перед проверкой квоты и сохранением. Штатные новые графические вложения phpBB подключены через core.modify_uploaded_file, без изменения ядра. Существующие файлы не обходятся и не пересжимаются.

- Сохраняются исходный формат, пропорции и прозрачность PNG/WebP. JPEG-ориентация EXIF переносится в пиксели перед удалением метаданных при перекодировании.
- PNG использует сжатие уровня 9 без потерь пикселей, если не требуется уменьшение размеров. JPEG и WebP — качество 85. При достаточной памяти изображения свыше 2560 пикселей по длинной стороне уменьшаются.
- Кандидат должен быть валидным, того же формата/ожидаемых размеров и минимум на 5% меньше оригинала. Иначе сохраняется оригинал.
- Учитывается лимит памяти PHP; дополнительная верхняя граница оценки — 128 МиБ. Крупное изображение при недостаточном бюджете не декодируется. Ограничения исходной загрузки до 2 МиБ/24 Мп для фотографий дел не увеличены.
- Неподдерживаемые GD-кодеки, ошибки обработки и анимированные PNG/WebP оставляют оригинал. Нет внешней отправки изображений или нового фонового сервиса.
- Кандидат создаётся рядом с исходником, проверяется и заменяет его атомарно. После проверки квоты файл переносится в приватное хранилище. В JSON сохраняются фактический size, original_size и optimized. При конфликте версии дела сохранённый новый файл удаляется прежней логикой отката.
- Фотографии по-прежнему выдаются только после проверки доступа, с правильным MIME и private/no-store. У обычных вложений формат и расширение не меняются; filedata.filesize обновляется до фактического размера. Внутренняя дополнительная проверка квоты phpBB может консервативно учитывать исходный размер файла.

Сжатие JPEG/PNG проверено в текущем работающем окружении для PNG и на GD-фикстурах для JPEG. Поддержка WebP зависит от сборки GD. Dockerfile дополнен libwebp-dev и --with-webp; для этой возможности требуется пересборка владельцем (`sudo bash scripts/start.sh`). Без неё поддерживаемые кодеки уже работают, остальные безопасно пропускают оптимизацию.

## Проверки

- GD-фикстура JPEG 3200×1800: 2 855 636 → 538 744 байта, 2560×1440. Это пример, не обещание процента для пользовательских материалов.
- Прозрачный PNG: 96 351 → 370 байт; полная и частичная прозрачность сохранены.
- Проверены EXIF-поворот, отсутствие увеличения файла, повторная оптимизация, очистка временных кандидатов и сохранение исходника при малом memory_limit.
- Реальная multipart-загрузка через PHP и phpBB request: PNG 1 503 010 → 2740 байт; move_uploaded_file и метаданные квоты корректны.
- Та же загрузка через действующий авторизованный портал: приватная выдача PNG 2740 байт, карточка перешла из синего «Создано» в зелёное «В работе».
- Сохранены проверки ложного изображения, SVG, превышения лимита и общей квоты.

Вспомогательный PHP CLI получил GD только в runtime из пакета php-gd Arch Linux для тестов; production использует свою существующую GD. Инструменты и фикстуры runtime не входят в публичные пакеты.

Команды: `bash scripts/php-local.sh -d extension="$PWD/runtime/usr/lib/php/modules/gd.so" tests/image_optimizer.php`; `UII_TEST_GD="$PWD/runtime/usr/lib/php/modules/gd.so" python3 tests/evidence_upload.py`. Последняя проверка использует временный HTTP-сервер и хранилище, не рабочую БД.

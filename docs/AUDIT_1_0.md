# Аудит и выпуск УИИ 1.0.0

Дата: 07.11.2026. Исходники: `/home/anrhangels/uii-forum`. Изменения разрешены пользователем после предварительного аудита. Нагрузочное тестирование рабочего сайта не проводилось.

## 1. Общая оценка архитектуры

phpBB 3.3.19, расширение uii/portal 1.0.0, отдельная тема UII Modern с наследованием prosilver. В Dockerfile PHP 8.3/Apache, в работающей базе MariaDB 10.11.19. Через авторизованный ACP подтверждены PHP 8.3.36, Apache 2.0 Handler, memory_limit 128M, post_max_size 8M, upload_max_filesize 2M. OPcache уже включён, объём 128 МиБ, validate_timestamps включён. Снимок разрешённых технических полей: runtime/test-results/php-web-audit.json. Версия вспомогательного локального PHP CLI — 8.5.12; его результаты не выдаются за характеристики production PHP.

Расширение содержит обработчики событий, маршруты, контроллер дел/сотрудников/настроек, сервисы ролей, навигации, статистики, фотографий и тем. Дела и история находятся в собственных таблицах; аккаунты, сеансы, права и обсуждения используют phpBB. Материалы дел — JSON payload. Задачи вычисляются при чтении; отдельная очередь не внедрялась. Штатные cron-механизмы phpBB сохранены. Фактический внешний системный cron и Docker RSS недоступны без прав на Docker.

Удаление ядра, стандартных библиотек и фоновых очисток не обосновано. Разделение большого контроллера не выполнялось ради самого рефакторинга: измеренного преимущества для текущей нагрузки нет.

## 2. Текущее состояние производительности

Подтверждено подключением к рабочей БД: InnoDB Buffer Pool 128 МиБ, max_connections 151, tmp_table_size/max_heap_table_size по 16 МиБ. Снимок технических значений и EXPLAIN: `runtime/test-results/database-audit.json`. Временные показатели зависят от момента запуска; status-счётчики накопительные и не являются измерением только УИИ.

На момент первого EXPLAIN оптимизатор оценивал около 34 строк дел. Реестр использовал activity_closed и сортировку, история дела — case_time и сортировку. Для статистики author_id OR assigned_id выбирался проход малой таблицы. Это не доказательство необходимости новых индексов. Схему рабочей БД, buffer pool и лимиты соединений не меняли.

Исходное приложение — около 23 МБ доступных файлов до добавления полного русского пакета. Размер исходников не равен RAM. Потребление всей системы около 200 МБ из ТЗ не подтверждено измерением и не считается дефектом само по себе. Нет сопоставимого замера времени до изменений; процент ускорения не заявляется. После изменений выполнены три последовательных локальных HTTP-запроса на страницу: медианы главной 4,4 мс, реестра 4,1 мс, задач 3,8 мс, управления 3,5 мс. Это короткий прогретый локальный замер, не p95 и не прогноз для хостинга; исходные выборки в runtime/test-results/http-timings.json.

## 3. Найденные и исправленные узкие места

- Список ответственных больше не выполняет запрос роли для каждого пользователя: одна выборка с EXISTS и проверкой действительных непредварительных групп.
- Аватары обсуждения используют uii_gender из уже полученной строки phpBB, без SQL на каждого уникального автора.
- Роль в подписчике событий запоминается только в пределах текущего объекта/запроса. Контроллер сохраняет собственный локальный кэш роли; глобальный межпользовательский кэш прав не вводился.
- Списки дел и главная не выбирают JSON payload без необходимости. Карточка и задачи по-прежнему получают материалы, которые реально используют.
- Значения конфигурации в контроллере повторно используются в пределах запроса; запись правила обновляет локальное значение.
- Сканирование фотографий на странице настроек выполняется только для роли, которой показывается заполнение.
- Удалена обработка всего HTML регулярным выражением ради замены тире. Исходное содержание отображается без такой замены.
- Сортировка дел имеет дополнительный ключ case_id. Это определяет порядок при одинаковом updated_at, но offset-пагинация не обещает снимок данных при параллельных изменениях.
- Добавлена навигация назад в реестр и журнал; задачи получили полноценные страницы с сохранением фильтра вместо ограничения первыми 50.

## 4. Уже реализованные оптимизации

Сохранены кэши phpBB/Twig, стандартная автозагрузка и контейнер; существующие индексы миграций v001–v014; ограниченные выборки и пагинация; JOIN авторов/исполнителей; вычисление задач без фонового размножения записей. Расширение OPcache установлено Dockerfile.

Текущий Apache уже отдаёт portal.css с gzip (при проверке 7061 байт вместо 31745 байт исходника). Подготовлены явные настройки OPcache с проверкой изменений файлов, сжатие CSS/JS/SVG и суточное публичное кэширование статических расширений. Конфигурация Apache не кэширует авторизованные HTML-страницы и маршруты приватных фото. Эти Docker-настройки вступают в силу после пересборки образа; доступ к Docker-сокету у процесса разработки отсутствует, поэтому пересборка не заявляется выполненной.

## 5. Возможности снижения ОЗУ

Уменьшены лишние выборки материалов и повторные операции. Дальнейшее изменение количества Apache-процессов и настроек БД требует измерения RSS/PSS и нагрузки. PHP-FPM не является схемой текущего Dockerfile; его pm-параметры здесь не применяются. Redis и новые постоянные службы не добавлялись.

## 6. Ускорение и интерфейс

Полный русский пакет переводчиков rxu/Olympusrupack закреплён коммитом и SHA-256; источник и лицензирование — RUSSIAN_SOURCE.md. Сохраняются термины УИИ поверх стандартного перевода. Автоматическая проверка: 5424 штатных ключа, нет отсутствующих ключей и несовместимых форматных аргументов. Технические идентификаторы, имена продуктов и внешние материалы не считаются переводимыми кнопками.

Портал и ACP получили согласованную тёмную палитру с фоном #080b10 и поверхностью #10161f. Проверка базовых текстовых токенов портала: минимум 4.77:1 в светлой и 6.50:1 в тёмной теме. Это не измерение контраста каждой возможной картинки и каждого экрана phpBB.

Центр управления группирует технические настройки по задачам. Ссылки содержат требуемый ACP SID и учитывают отдельные права. Сохранены штатные модули, повторная авторизация и серверные проверки. В ACP русские объяснения связаны с полями через aria-describedby. В материалах дел добавлены подсказки, формат даты и условия обязательности; вид проверки выбирается из списка. С формы входа убран флажок скрытия активности.

Установщик поставляется отдельным пакетом новой установки: native phpBB, русский язык по умолчанию, единое оформление, доступные поля и светлая/тёмная темы. В действующем сайте install отсутствует. CLI завершает настройку УИИ, выбирает стиль, закрывает регистрацию, отключает VigLink/CDN и переносит установщик в приватную папку.

## 7. Совместимость с PHP-хостингом

Docker не обязателен для выполнения приложения. Нужны совместимый PHP >=8.1, MySQL/MariaDB, необходимые расширения, права служебных каталогов, HTTPS и приватное хранилище фото. CLI нужен для описанной завершающей настройки; при его отсутствии требуется помощь провайдера. Для nginx правила Apache .htaccess не действуют. Готовность конкретного бесплатного тарифа не подтверждена без проверки его ограничений. Инструкция SpaceWeb сохранена отдельно.

## 8. Выполненный план и проверки

Этап I: переводы, тёмная тема, доступность полей, группировка администрирования и устранение очевидных лишних операций.

Этап II: сокращение SQL, выборок и обходов файлов; пагинация; диагностика реальных индексов. Новые индексы и уменьшение памяти не потребовались по текущим данным.

Этап III: воспроизводимый пакет новой установки, завершающий CLI и руководства. Миграция платформы на другой стек, FPM и переделка хранения payload отложены до измеренной необходимости.

Подтверждены: синтаксис шаблонов и PHP; проверки доменных правил, ролей, загрузок, SQL-статистики и фильтров; штатные словари; целостность исходного ядра/prosilver; фактический браузерный проход 13 ссылок ACP, обеих тем, форм и ширин 360/768/1440. Чистая установка и миграции УИИ выполнены во временной директории с отдельным случайным префиксом таблиц uiiqa_; после проверки удалены только эти 72 тестовые таблицы. Это не импорт в production и не подтверждение установки у внешнего провайдера.

HTTP-проверки используют явно помеченные QA-записи. Тестовая авторизация усилена: проверяется наличие формы входа/редиректа, а не слово «неверный» в HTML (теперь оно легитимно присутствует в русском тексте AJAX-ошибки). Из старого общего прогона исключён сценарий удалённого календаря. Используемый тестовый администратор задаётся переменной окружения; реальные пароли не сбрасываются.

Актуальные подробные логи — runtime/test-results/audit-full.log и audit-ui.log. Окончательный статус общего прогона фиксируется в WORK_REPORT_1_0.md. Нагрузочные тесты на 20 пользователей не запускались.

## 9. Риски и откат

До изменений сохранены `snapshots/pre-audit-20261107-132204.tar.gz` и `snapshots/database-local-20261107-102627.sql`. Кэш перемещён в отдельный снимок перед пересборкой. Фотографии не удалялись. Секреты в публичные архивы не включаются.

Кодовые изменения 1.0.0 не требуют изменения схемы рабочей БД. Откат — прежние собственные файлы и сброс кэша. Полный импорт старой БД ради отмены оформления недопустим: он потеряет последующие дела. Для серверного отката восстановите прежний Dockerfile/конфигурации и образ, сохранив volume. Для установки с нуля используется отдельная пустая база; не запускайте установочный процесс поверх действующей установки.

Защита версий, транзакции дел, CSRF, доступ к связанным темам, приватная выдача фото и блокировка загрузок сохранены. Дополнительно два разных пользователя одновременно закрывали одно QA-дело: одна операция успешна, одна отклонена, версия 2, одно событие close и заблокированная тема. Лог: runtime/test-results/concurrent-close.log. Этот функциональный сценарий не является нагрузочным испытанием всех гонок.

## 10. Подтверждение и эксплуатационные ограничения

Реализация разрешена сообщением пользователя «Приступи к полной работе над проектом» и продолжена после запуска сайта пользователем. Дополнительное согласование требуется для нагрузки на рабочий сервер, удаления пользовательских данных или непредусмотренной смены инфраструктуры.

Готовые инструкции: ADMIN_GUIDE_RU.md, INSTALL_RU.md и spaceweb.md. После пересборки Docker нужны проверка заголовков статики и актуального web OPcache, резервное копирование и обычная приёмка владельцем. Гарантия отсутствия любых багов не заявляется.

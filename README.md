## Запуск и остановка

```bash
cd /home/anrhangels/uii-forum
sudo bash scripts/start.sh
sudo bash scripts/stop.sh
```

База хранится в Docker volume `database` и сохраняется между перезапусками. Не применять `docker compose down -v`: команда уничтожает volume. `.env` уже создан; реквизиты не включать в публичные архивы или переписку.

Обновление расширения с резервной копией, lint, доменными тестами, миграциями и очисткой кэша:

```bash

```

Код содержит миграции v001-v014. Актуальное состояние базы проверяется при обновлении; в этой сессии v014 не применялась. Обновление повторяемое. Из-за особенностей прав Docker из среды разработки также подготовлен локальный PHP CLI в `runtime/`; это вспомогательный инструмент, в production он не требуется. Его конфигурация подключается к локальной Docker-базе по IP моста; при смене адреса использовать стандартные Docker-скрипты.

## Что работает

- UII Modern: панель сотрудника с реальными счётчиками, последние дела и действия, боковая навигация, мобильное раскрывающееся меню, светлая/тёмная тема с сохранением выбора.
- Группы `UII_FACTION`, `UII_CHIEF`, `UII_DEPUTY`, `UII_STAFF`. Учётные записи phpBB, проверка прав на сервере. Основатель phpBB включён в руководство фракции.
- Создание сотрудника, случайный временный пароль, одноразовая выдача TXT в ответ на создание/сброс, обязательная смена пароля, блокировка/восстановление, роль и пол персонажа, профиль и последний вход. Самостоятельное повышение роли запрещено. Начальник и заместитель управляют обычными сотрудниками; руководство фракции назначает руководящие роли. Основатель phpBB защищён от изменения через форму сотрудников.
- Жалобы: заявитель, фигурант, основание, структурированные поля протокола, документы, решение, нарушения/отсутствие нарушений, наказание, закрытие руководителем после заполнения обязательных данных.
- Запросы: доказательства запроса, уведомления и публикации; серверные 48 часов; состояния ожидания, просрочки и своевременного/позднего ответа; завершение. Руководитель может завершить просроченный запрос без ответа, указав основание; отсутствие ответа сохраняется отдельно от факта завершения.
- Проверки: плановая/внеплановая, дата и время, начало, доказательства, результат, отмена и завершение.
- Новое дело создаёт отдельную тему в соответствующем служебном разделе phpBB. В теме есть ссылка на карточку; закрытие дела блокирует обсуждение. Дополнения дела сохраняются в структурированных полях, комментарии — в теме.
- Назначение ответственного руководителем, реестр, поиск по названию, фильтры запросов, общий архив всех типов дел, журнал изменений и административных операций.
- Вычисляемые задачи с фильтрами: мои, все (руководству), срочные, просроченные, завершённые. Нет фоновых процессов или создания дубликатов при просмотре.
- CSRF, экранирование, SQL escaping/целочисленные параметры, проверка HTTP(S)-ссылок, контроль версии при редактировании. Обычный сотрудник видит свои и назначенные дела; руководство — все. Проверяются также прямые ссылки на форумные темы.

## Язык и исходные RP-материалы

Все собственные экраны написаны на русском. Локаль `ru` — авторский пакет УИИ с английским резервным словарём. Переведены основные элементы входа, навигации, документов, дат, сообщений и ошибок. Это **частичная**, а не полная русификация стандартного phpBB: в ACP, справке и редких системных экранах остаются английские строки. Официальный пакет скачать не удалось; авторская локализация не выдаётся за официальный перевод.

В `reference/` сохранены исходные СЗ.txt и УИИ.txt. Шаблон СЗ связывает 48 часов с публикацией, ТЗ — с уведомлением: режим выбирается начальником в настройках. Уже начатые сроки при смене режима не изменяются. УИИ.txt — пример заключения, шаблона опроса нет. Поля протокола помечены предварительными и могут быть скорректированы. Дополнительные ограничения завершения — текущая логика приложения, не официальный RP-регламент.

Настройка общая, сохраняется по CSRF и версии с записью в журнал. Маршруты и права закреплены каталогом: перестановка пунктов не выдаёт доступ. Пустые группы скрываются, удалить можно только пустую группу; обязательные ссылки сохраняются.

В ACP отключены модули уже отключённых функций и их прямые адреса: PM/почтовая рассылка, подписи, свободные аватары, RSS, значки/смайлы/звания, боты, дополнительные поля профиля, неактивные регистрации, массовая очистка. Обслуживание базы, форумные разделы, права, безопасность, CAPTCHA входа, стили и расширения сохранены. Ядро физически не вырезалось: оно нужно совместимости, аккаунтам и обсуждениям.

## Подготовка SpaceWeb - 0.9.1

Текущая цель переноса - **SpaceWeb**, обычный виртуальный хостинг PHP/MySQL. Инструкция: [docs/spaceweb.md](docs/spaceweb.md).

Кодовый пакет (без данных): `python3 scripts/prepare-spaceweb.py`. Полный пакет свежей базы и файлов: `sudo bash scripts/prepare-spaceweb.sh [домен.ru]`. Полный сборщик сначала делает резервную копию/обновление, затем на время экспорта приостанавливает web и всегда возобновляет его. Данные исходной установки не удаляются.

Пакет разделён: website.zip для корня сайта, private-files.zip для приватной папки рядом с public_html, database.sql.gz для импорта в новую базу, SQL настроек и инструменты CLI. Префикс таблиц берётся из проекта, локальные пароли не переносятся. В новом config.php нужно заполнить реквизиты SpaceWeb. До завершения настройки действует .uii-deploy.lock. MySQL 8 SpaceWeb: 127.0.0.1:3308 по документации провайдера, сверить с аккаунтом.

Хранилище фото поддерживает UII_EVIDENCE_PATH: локально остаётся прежний files/uii_evidence, в пакете переноса - приватная папка вне веб-корня. Квота в любом месте - 500 МиБ, счётчик настроек использует тот же путь. Пример и проверки - в private-tools/setup-spaceweb.php; инструмент не публикуется в public_html, сверяет ссылки на фото до открытия доступа.

У кодового пакета в deployment.json complete_for_migration=false. Старые дампы не выдаются за свежий экспорт. Настоящий полный экспорт не выполнялся агентом из-за недоступности Docker и закрытых файлов; запуск prepare-spaceweb.sh владельцем завершает сборку.
